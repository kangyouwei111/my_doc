# 团队协作

文档和代码一样需要评审。把文档变更放在 Pull Request 中，团队就能在发布前发现过时信息、缺少前置条件或含糊的操作步骤。

## 推荐的 Pull Request 描述

```md
## 这次更新解决什么问题？

## 谁需要阅读？

## 如何验证内容正确？

## 是否需要同步其他页面？
```

## 写作约定

- 标题使用读者能搜索到的词，不使用「说明」「杂项」等空泛名称。
- 命令和路径使用代码格式，关键步骤使用有序列表。
- 描述行为时使用现在时，避免把临时状态写成长期规则。
- 页面顶部标明适用版本，发生破坏性变更时补充迁移说明。

::: tip 保持页面可维护
发现一处错误时，顺手修正链接、示例和目录。小而完整的变更，比积累到下一次大整理更容易被评审。
:::
