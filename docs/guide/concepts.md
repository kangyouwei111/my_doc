# 核心概念

Papertrail 用三个概念组织知识：页面、集合和决策。

## 页面

页面是最小的可阅读单元。每页只解决一个明确问题，并在开头说明读者和目标。

推荐结构：

1. 这页解决什么问题
2. 读者需要准备什么
3. 按顺序执行的步骤
4. 例外情况与下一步

## 集合

集合是有共同上下文的一组页面，例如「入职」「发布」或「API 参考」。集合通过侧边栏表达，不需要把所有内容塞进一页长文档。

## 决策

决策记录的是选择，而不是过程流水账。一个好的决策记录应包含背景、选项、结论和影响。

```md
## 决策

选择使用 GitHub Pages 发布静态站点。

## 原因

部署成本低，且与仓库权限和评审流程保持一致。
```

::: details 页面应该多长？
以读者完成一次任务所需的长度为准。超过 10 分钟仍找不到重点时，优先拆分页面，而不是继续增加目录层级。
:::
