# 工作流总览

一个可复用的文档工作流通常包含四步：发现、整理、评审、发布。

```text
发现问题 → 写出最小答案 → Pull Request 评审 → 合并并自动发布
```

## 发现问题

从支持请求、事故复盘和重复提问中寻找文档缺口。先记录问题原话，再决定它应该归到哪个集合。

## 写出最小答案

先让读者完成任务，再补背景。使用真实命令和可验证的预期结果，避免只有概念没有动作。

## Pull Request 评审

评审重点不只是错别字，还包括：前置条件是否完整、步骤是否可执行、链接是否有效，以及内容是否与代码版本一致。

## 合并并自动发布

合并到 `main` 后，GitHub Actions 会运行 `pnpm build`，再将构建产物发布到 GitHub Pages。发布失败时，先查看 Actions 日志，再在本地复现同一条构建命令。

相关检查项请看 [发布检查清单](/workflow/release-checklist)。
